# 커밋 메시지 규칙

이 문서는 이 프로젝트에서 새로 생성하는 커밋 메시지 형식의 정본이다. 기존 커밋 이력에는 소급 적용하지 않는다.

## 기본 구조

- **제목**: 변경 사항을 요약한 짧은 한국어 개조식 문구
- **본문**: 무엇을, 왜 변경했는지 설명하는 한국어 개조식 문구이며 필수

제목과 본문 사이는 빈 행 하나로 구분한다. 본문은 한 줄에 한 항목만 작성한다. 같은 문단의 항목은 빈 행 없이 줄바꿈하고, 맥락이 달라 한 문단을 이룰 수 없는 항목은 빈 행 하나로 문단을 나눈다.

```text
Unity VCS 증거 하네스를 추가

Scene과 Prefab의 저장 변경을 의미 단위로 수집
읽기 전용 명령만 허용해 파일 변경을 방지

조사와 완료 검증이 같은 공용 수집기를 사용하도록 연결
```

## 작성 규칙

1. 제목과 본문은 정확히 빈 행 하나로 구분한다.
2. 제목은 Unicode 문자 기준 50자 이내로 작성한다.
3. 제목과 본문의 모든 내용 줄에는 한글을 하나 이상 포함한다. `Unity`, 클래스명, 파일 경로, 버전 같은 영문 식별자와 고유명사는 함께 사용할 수 있다.
4. `Add`, `Fix`, `Update` 같은 영문 명령 동사로 시작하지 않는다. `Unity VCS ...`처럼 영문 고유명사로 시작하는 한국어 문구는 허용한다.
5. 제목과 본문은 `추가`, `수집`, `방지`, `연결`처럼 종결 어미를 붙이지 않은 명사형 개조식으로 작성한다.
6. 제목과 본문 줄 끝에는 `.`·`!`·`?`와 이에 대응하는 전각 종결 부호를 붙이지 않는다.
7. 본문은 필수이며 변경한 내용과 변경 이유를 설명한다.
8. 본문은 한 줄에 한 항목만 작성한다.
9. 같은 문단을 이루는 항목은 빈 줄 없이 줄바꿈만 한다.
10. 서로 다른 문단은 정확히 빈 행 하나로 구분하며 연속된 빈 행을 두지 않는다.

문구가 실제로 같은 문단을 이루는지는 작성자가 판단한다. 자동 검사는 작성자가 선택한 문단 경계의 줄 간격만 검사한다.

## 자동 검사 범위

`.githooks/commit-msg`는 새 커밋이 생성되기 전에 다음 항목을 검사한다.

- 제목 존재 여부
- 제목 길이
- 제목과 본문 각 내용 줄의 한글 포함 여부
- 영문 명령 동사 시작 여부
- 본문 존재 여부
- 제목과 본문의 개조식 끝맺음
- 제목·본문 줄 끝의 종결 부호
- 제목과 본문 사이의 빈 행 수
- 본문 문단 사이의 연속 빈 행

본문이 실제로 변경 내용과 이유를 설명하는지, 각 항목이 의미상 같은 문단을 이루는지는 기계적으로 판정하지 않는다. 작성자와 검토자가 확인한다.

Git이 자동 생성한 영어 `Merge`·`Revert` 제목도 예외로 두지 않는다. 커밋 전에 이 규칙에 맞는 한국어 메시지로 바꾼다. `fixup!`과 `squash!` 형식은 현재 허용하지 않는다.

## 활성화

clone마다 한 번 다음 명령으로 저장소가 버전 관리하는 Git 훅을 활성화한다.

```bash
git config --local core.hooksPath .githooks
```

세션 시작 시 하네스 닥터가 이 설정과 훅 진입점의 존재 여부를 검사한다.
