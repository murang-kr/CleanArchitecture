# 요구사항 확인

현재 맥락에서 목표·대상·완료 기준을 먼저 찾는다. 합리적인 기본값이 있거나 이미 결정된 사항은 다시 묻지 않는다. 명확한 소수정·승인된 후속 작업에는 인터뷰를 적용하지 않는다.

- 가정이 틀리면 결과가 크게 달라지는 지점을 우선 확인한다. 내부 구현 방식보다 무엇을 왜 만드는지와 범위를 먼저 다룬다.
- 필요한 질문만 짧게 묻는다. 선택지가 이해에 도움이 되면 구체적인 차이와 권고를 제시한다. 모호성 점수·가중치·임계값을 계산하지 않는다.
- 답변을 기다리는 동안 독립적인 조사·준비는 계속한다. 승인이나 필수 답변이 필요한 변경은 답변 없이 진행하지 않는다.
- 추가 질문이 결과를 바꾸지 않으면 반복하지 않는다. 해결된 요구·채택한 가정·남은 결정 경계를 짧게 정리한다. 중요한 미확정 요구가 남았다면 진행 가능한 범위와 필요한 답변을 구분한다.
- 인터뷰 결과가 계획에 필요한 경우 목표·완료 기준·제외 범위·사용자 결정 사항을 Seed 요약으로 남긴다. 맥락에서 명확한 항목은 질문 없이 정리한다.

이후 구현은 `plan-gate`를 따른다. Seed에 없는 범위 확대를 인터뷰 결과로 정당화하지 않는다.
