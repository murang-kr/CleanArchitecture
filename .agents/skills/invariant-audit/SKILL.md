# 반복 실패 진단

파일 편집 횟수만으로 발산을 판정하지 않는다. 편집 훅은 성공·실패를 판정하지 않는 참고 알림이다. 독립 요청·단계적 구현·사용자 튜닝은 계속하며 알림만으로 중단·승인 요청·면제 보고를 하지 않는다.

실제 같은 문제의 실패가 반복되면 다음 맹목 패치 전에 해당 서브시스템을 다시 관측한다. 같은 턴 안의 반복 실패에도 적용한다.

1. 실패한 시도와 재현·테스트 결과를 대조한다. 해결되지 않은 현상이 같은 문제인지 확인한다.
2. 관련 코드를 읽고 항상 지켜야 할 불변식, 상태 변수·전이, 복수 실행 경로와 경계 조건을 필요한 범위에서 정리한다.
3. 각 시도의 가정이 어느 관측과 충돌했는지 확인하고 다음 가설을 재현 방법과 연결한다.
4. 근거가 생기면 승인된 범위 안에서 수정·검증을 계속한다. 원인이 불명확하면 더 좁은 재현·관측을 진행한다. 추가 권한·요구 결정이 필요하거나 가능한 진단을 소진했을 때 시도와 필요한 도움을 보고한다.

실패 테스트 삭제·완화, 판정 우회, 완료를 위한 범위 축소는 금지한다. 원복이 필요해도 기존 사용자 변경을 보존하고 Git 승인 규칙을 따른다. 진단은 원래 작업의 일부이며 무관한 문제로 범위를 넓히지 않는다.
