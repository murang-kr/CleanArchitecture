# 불변식 감사 — 편집 루프 가드 착지 절차

같은 파일을 서로 다른 3개 턴에서 수정했다는 것은 "고쳤는데 안 고쳐져서 다시 건드리는" 발산의 신호일 수 있다. 아래 절차를 순서대로 따른다.

## 0. 면제 판정 — 해당하면 한 줄로 사유만 밝히고 원래 작업을 그대로 계속

- 사용자가 명시적으로 반복 수정을 지시한 경우 (수치 튜닝, 순차적 추가 요청 등)
- 각 턴의 수정이 서로 독립적인 별개 요구였던 경우
- 승인된 계획에 따라 같은 파일을 단계적으로 완성 중인 경우

핵심 질문: **"같은 문제를 다시 고치고 있는가, 아니면 다른 일로 같은 파일을 지나는가?"** 전자만 발산이다.

면제 사유 한 줄은 **사용자에게 보이는 응답 본문에** 남긴다 — 내부 추론(thinking)에서만 판정하고 지나가면 이행이 아니다. 사용자는 가드가 발동한 사실만 보고 결론을 못 보는 상태가 된다.

## 1. 멈춤

지금 떠올린 다음 수정안을 실행하지 않는다. 실패한 패치가 3개면 코드가 아니라 모델(이해)이 틀렸을 확률이 높다 — 각 패치는 부분만 본 국소 수정이었고, 전체 그림이 틀리면 경로 A를 잡으며 경로 B를 깨는 두더지잡기가 된다.

## 2. 불변식 나열

수정 중인 서브시스템에서 **항상 참이어야 하는 것**들을 나열한다.
(예: "데미지는 반드시 이 감산 경로를 거친다", "이 상태에서 저 컴포넌트는 반드시 존재한다")

- 코드를 실제로 읽고 나열한다 — 기억·추측 금지 (evidence-analysis 원칙 준용)

## 3. 상태 공간 나열

- 상태 변수와 가능한 값
- 상태 전이 — 무엇이 언제 바꾸는가
- **복수 경로 여부** — 같은 결과에 도달하는 다른 코드 경로가 있는가 (예: 직통 경로 vs 뷰 경로)
- 경계 조건 — 0/최소/최대, 동시성, 프레임·실행 순서

## 4. 시도 대조

지금까지의 수정 시도 각각에 대해: 어떤 불변식·경로를 가정했고, 나열 결과와 어디가 어긋나는지 적는다. 다음 수정안은 이 목록과 대조해 어긋남이 없을 때만 실행한다.

## 5. 3회 실패 프로토콜

- **샷건 디버깅 금지** — 가설 없이 여러 곳을 찔러보는 수정 금지
- **통과 조작 금지** — 실패 테스트 삭제·완화, 스코프 축소로 "완료" 만들기 금지
- 모델 재구축 후에도 원인이 안 보이면: 마지막 정상 상태로의 원복을 검토하고, 시도 내역과 나열 결과를 요약해 **다음 맹목 패치 대신 사용자에게 에스컬레이션**한다

## 6. 복귀 — 이 감사는 원래 작업의 서브스텝이다

- 나열은 지금 수정 중인 서브시스템에 한정한다
- 감사가 끝나면 즉시 원래 작업으로 복귀한다
- 감사 중 발견한 무관한 문제는 고치지 말고 보고만 한다
