# 위임 계약

## 위임 판단

- 작업이 작거나 강하게 결합돼 있으면 직접 수행한다. 팬아웃 자체가 비용이다.
- 경계가 명확하고 독립적으로 검증 가능한 작업만 위임한다.
- 파일·상태를 공유하지 않는 독립 작업만 병렬 실행한다. 의존성이 있으면 순차로 진행한다.
- 에이전트 수는 작업이 자연스럽게 분해되는 수를 따르며, 머릿수를 늘리기 위한 분해는 하지 않는다.

## 위임 프롬프트

결과물을 만드는 위임에는 다음 정보를 포함한다.

1. **TASK** — 수행할 일
2. **EXPECTED OUTCOME** — 반환할 결과물 형태와 필수 증거
3. **MUST** — 프로젝트 관례와 검증 방법을 포함한 필수 조건
4. **MUST NOT** — 범위 밖 수정, 추측 서술 등 금지 사항
5. **CONTEXT** — 대화 없이도 작업할 수 있는 필요한 배경
6. **STOP WHEN** — 완료·중단 조건과 막혔을 때 보고할 내용

검색·확인·요약 같은 조회성 위임은 `TASK`와 `CONTEXT`만으로 충분하다.

## 결과 판정과 후속 작업

- 에이전트의 완료 선언이 아니라 반환된 파일, 출력, 테스트 결과 등 증거로 완료를 판정한다.
- 증거가 없으면 미완료로 취급한다.
- 같은 에이전트에 이어지는 후속 작업은 새로 만들지 않고 기존 에이전트에 보낸다.
