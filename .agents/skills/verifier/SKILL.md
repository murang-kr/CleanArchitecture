# 완료 증거 검토

완료 선언 대신 실제 산출물과 실행 결과로 판정한다. 중요한 변경의 독립 검토가 필요하면 `delegation` 계약으로 위임하고, 직접 수행할 때도 구현 판단과 구분된 검토 패스로 진행한다.

## 절차

1. 요구사항·변경 파일·제약과 원본 증거를 대조한다. 실행 명령, 검사 대상, 종료 상태, 실패·생략 수와 실행 이후 관련 코드·설정·환경 변경 여부를 확인한다.
2. 현재 변경과 일치하는 이번 작업의 원본 출력은 재사용한다. 다른 에이전트의 요약·완료 선언만 전달받았다면 원본 출력과 산출물을 읽는다.
3. 증거 누락·불일치·관련 변경·비결정적 실패 우려 또는 중요한 위험의 독립 재현이 필요한 항목만 재실행한다. `.codex/harness-bindings.json`(없으면 `.claude/harness-bindings.json`)이나 프로젝트 문서의 해당 대상 검증 명령을 사용한다. Node 하네스에 Unity 컴파일을 일괄 적용하지 않는다.
4. 요구 누락, 범위 밖 수정, 실패 테스트 삭제·완화, 테스트 전용 판정 우회가 없는지 확인한다.

Scene·Prefab 변경은 `unity-vcs-evidence`가 있을 때 같은 비교 기준의 E1 JSON을 예상 `asset / owner / component / raw fields / change kind`와 대조한다. `uncertainMatches > 0` 또는 `valuesTruncated: true`이면 완전 통과가 아니다. 현재 Editor·런타임 동작은 필요한 E2–E4 증거를 추가한다. 스킬·실행 환경이 없으면 해당 관측의 한계를 명시한다.

## 판정

`PASS` / `FAIL` / `PARTIAL`과 핵심 근거·검증 범위를 반환한다. 계획 작업은 V0–V2를, Unity 상태 주장은 관측한 E1–E4를 구분한다. 재사용한 증거와 재실행한 검사를 밝히며, 판정 불가 항목은 이유와 함께 남긴다. UX·체감 등 사람 검수가 필요한 항목은 해당할 때만 추가한다.
